2.2 API Design Principles
PreOne APIs 10 core principles follow कारत(cid:2)त. हा(cid:8) principles ADR-001 (API Design Principles) मध्ये(cid:8)
formalized आहा(cid:8)त आणि(cid:11) Governance Board द्वा(cid:2)र(cid:8) enforced:
Principle Description
REST First Resource-based URLs, standard HTTP methods,
JSON payloads. No RPC-style endpoints unless
absolutely necessary (e.g.,
/admissions/{id}/approve is an exception pattern
for state transitions).
JSON Only Request and response bodies are always
application/json. No XML, no form-encoded
bodies (except multipart/form-data for file
uploads).
Stateless Every request contains all context (auth, tenant,
locale). Server does not maintain session state
between requests. Enables horizontal scaling.
Resource Based URLs name resources (nouns), not actions (verbs).
Plural nouns: /students, /invoices, /attendance.
Sub-resources: /students/{id}/guardians.
Versioned URI path versioning /api/v1/, /api/v2/. Backward-
compatible changes within a major version.
Breaking changes require new major version with
12-month overlap.
Idempotent POST/PUT/PATCH support Idempotency-Key
header. Same key + same payload returns cached
response. Mandatory for payment, admission, file
upload endpoints.
Secure by Default TLS 1.3 mandatory. JWT 15min access, 30day
refresh. PII encrypted at rest (pgcrypto). Rate-
limited per IP + per user. DPDP Act compliance
built-in.
Multi-Tenant Aware Every request scoped via X-Tenant-ID, X-School-
ID, X-Branch-ID headers. Row-level security
enforced at DB layer. No cross-tenant data access
without explicit platform-admin scope.
OpenAPI First Spec is source of truth. NestJS swagger decorators
generate openapi.json. Redoc renders docs.
Postman collection auto-generated. SDK auto-
generated for TypeScript/Python.

23.3 Event Rules
• Event schema registry: JSON Schema per event, versioned (semver), published to internal

• Event versioning: backward-compatible changes (add fields) increment minor; breaking

state from event log.

• Dead letter queue: events that fail processing after 5 retries → DLQ for manual review.
• Event replay: admin can replay events from event_store to rebuild read models or retrigger
notifications.
